Unified TTS + S2T

两个任务，一份伪代码

每个数字都是从运行中的模型打印出来的。两个任务的张量序列长度相同（560），但 flow 真正作用的位置数差 9 倍 —— 这是理解整件事的关键。

任务定义

TTS 和 S2T 分别在做什么

TTS 语音通道是目标

给什么
一段文本（转录），加上可选的前 K 帧真实 mel 作为 voice prompt（告诉模型用谁的嗓音）
生成什么
512 帧 log-mel，100 维每帧。再过冻结的 Vocos 声码器变波形
flow 作用在
z_V，语音通道，音频区的非 prompt 位置
条件是
升采样到帧率的文本 latent（在 z_T 的音频区）＋ token 区的干净 T5 latent ＋ 升采样字符嵌入（cond）＋ voice prompt 那几帧干净 mel
有效长度
平均 422 个位置参与 flow loss（512 帧减去 voice prompt 和 padding）
decode head
不启用。连续目标没有 token 可预测

S2T 文本通道是目标

给什么
一段音频。原始 mel 填在 z_V 并全程钉死为干净；同时它的冻结 Whisper 特征经投影加进 z_T 的音频区
生成什么
48 个位置的 T5 latent（512 维每个），再经 ELF 预训练的 decode head 变成 token id
flow 作用在
z_T，文本通道，只在 token 区
条件是
音频区的干净 mel ＋ 投影后的 Whisper 特征。cond 块为 0 —— 还不知道文本
有效长度
恰好 48 个位置（max_text），真 token 约 19 个，其余补 pad，模型要自己学会在哪里停
decode head
启用，概率 Bernoulli(0.2)。这里 ELF 的 late discretization 真正用上了
同一个张量，9 倍的有效长度差。两个任务的序列都是 560 个位置、都过同一个 12 层 transformer，flow loss 的位置数却是 422 对 48。所以 S2T 的学习信号本来就稀疏得多 —— 实测这正是它更难的原因之一：同一布局下没有 Whisper 时，S2T 的 token 准确率 30,000 步只爬到 2.5%，而换成逐帧升采样的冗余目标（每 token 约 27 个位置）能爬到 11.2%。

序列长度

560 是怎么来的

TTSS2T怎么定的
张量序列长度 L560560max_length，我们选的。RoPE 表按它建，所以每行必须正好这么长
音频区512 帧512 帧max_length − max_text。512 帧 @93.75Hz = 5.46 秒
token 区48 位置48 位置max_text，取 t5 token 数的 p99 之上
真实 token 数 N约 19约 19文本本身决定，不足 48 的补 pad
flow loss 的位置数约 42248TTS = 音频区 − voice prompt − padding；S2T = 整个 token 区
条件位置数约 592约 439通道×位置的计数，所以可以超过 L
padding约 29约 73短于 512 帧的音频、以及 token 区未用满的部分

伪代码

完整流程

变量名和真实代码一致（unified.py / train_unified.py），可以直接对照。

A · 一次性预处理（离线）

# 每条音频做一次，结果写进 memmap 缓存
for 每条音频 (wav, 转录) in 数据集:
    w   = resample(wav, → 24000 Hz)
    mel = VocosMel(w)                      # 冻结，0 参数。(T, 100) @93.75Hz
    chars = [stoi[c] for c in 转录.lower()]  # 字符 id，词表 40
    t5    = T5Tokenizer(转录.lower())        # token id。小写很重要：
                                           # 大写会被 sentencepiece 切碎
    w16 = resample(wav, → 16000 Hz)
    wh  = WhisperEncoder(w16)[:真实长度]    # 冻结 88.2M。(M, 768) @50Hz

# 全局统计，用来归一化
latent_mean, latent_std = mel 的均值与标准差   # LJSpeech: −1.4747 / 1.9931

B · 构造一个 batch 行

L, max_text = 560, 48
max_mel     = L − max_text          # 512
tok0        = max_mel               # token 区固定从第 512 位开始，
                                    # 这样它的 RoPE 位置不随音频长度漂移

task = S2T if rand() < p_s2t else TTS   # 逐样本抽，不是交替步数

# ---- 裁剪：音频和转录必须同步裁，否则 S2T 被要求"听 5 秒写 12 秒"
T = min(T_full, max_mel)
a = randint(0, T_full − T)                      # 裁剪起点
c0, c1 = ⌊a·N_chars/T_full⌋, ⌈(a+T)·N_chars/T_full⌉
转录片段 = 转录[c0:c1] 并对齐到词边界
tok      = T5Tokenizer(转录片段);  N = len(tok)

# ---- 三个通道，两个区
mel_norm = (mel[a:a+T] − latent_mean) / latent_std       # (T, 100)
x0_V[0:T]           = mel_norm                      # 语音通道，只在音频区
x0_T[tok0:tok0+N] = T5Encoder(tok) / 0.2            # 文本通道，token 区

if task == TTS:
    up = ⌊arange(T)·N/T⌋                                 # 短→长，整段复制
    x0_T[0:T] = T5Encoder(tok)[up] / 0.2             # 升采样文本，做条件
    cond[0:T] = CharEmbed(chars_upsampled[a:a+T])
else:  # S2T
    wi = ⌊(a + arange(T)) · 50/93.75⌋                     # Whisper 50Hz → 我们 93.75Hz
    whisper_feat[0:T] = wh[wi]                            # 之后在 forward 里投影进 x0_T
    cond[:] = 0                                           # 还不知道文本

# ---- 谁干净、谁加噪：按通道标，不是按位置
if task == TTS:
    prompt_T[:] = 1                  # 全部文本都是条件
    K = int(T · uniform(0, 0.3));  prompt_V[0:K] = 1   # voice prompt
else:
    prompt_V[0:T] = 1               # 音频全部是条件
    prompt_T[:] = 0                  # token 区是目标

C · 一步训练（三次 forward）

# ---- 1. 加噪。每行一个 t，两个通道共享（因为每行只有一个通道加噪）
t = sigmoid(randn() · 0.8 + (−1.5))        # 均值 0.209，中位 0.182
z_V = t·x0_V + (1−t)·randn()·2.0;  z_V = where(prompt_V, x0_V, z_V)
z_T = t·x0_T + (1−t)·randn()·2.0;  z_T = where(prompt_T, x0_T, z_T)

# ---- 2. 两次 no_grad forward，构造 ELF 的自条件 CFG 目标
sc_cfg = uniform(1, 3)
with no_grad:
    x_u = model(z_T, z_V, sc=0,   task, whisper_feat)   # 自条件为零
    x_c = model(z_T, z_V, sc=x_u, task, whisper_feat)   # 自条件为 x_u
    v_u = (x_u − z)/clamp(1−t, 0.05)
    v_c = (x_c − z)/clamp(1−t, 0.05)
    guidance = (1 − 1/sc_cfg) · (v_c − v_u)
    if rand() > 0.5:  guidance = 0                      # 一半的行丢掉
    v_target = (x0 − z)/clamp(1−t, 0.05) + guidance

# ---- 3. decoder 分支：只给 S2T 行，而且 t 直接设 1
d = Bernoulli(0.2) · (task == S2T)
λ = sigmoid(randn() · 0.8 + (−0.5))       # audio forcing：原值 +0.8
z_T_in = d ? (λ·x0_T + (1−λ)·randn()·5.0) : z_T
t_in   = d ? 1.0 : t

# ---- 4. 带梯度的那一次
x̂_T, x̂_V, logits = model(z_T_in, z_V, sc=x_u·use_sc, t_in, task, whisper_feat,
                          decode_head_active=d)

# ---- 5. loss：L2 只作用在该行加噪的那个通道
L2 = task==S2T ? ‖(x̂_T−z_T)/(1−t) − v_target_T‖²
                : ‖(x̂_V−z_V)/(1−t) − v_target_V‖²
CE = CrossEntropy(logits, token_ids)                     # 只 S2T 行有意义

m      = flow 目标位置的 mask     # TTS ≈ 422 个，S2T = 48 个
m_ce   = m · d;   m_l2 = m · (1−d)
loss   = ( Σ CE·m_ce + Σ L2·m_l2 ) / Σ m   # 同一个分母！
                                   # 所以 0.2 就是 CE 的实际权重
loss.backward();  clip_grad_norm(1.0);  AdamW.step()
EMA ← 0.9995·EMA + 0.0005·model

D · 推理（采样）

NFE = 32
ts  = linspace(0, 1, 33)              # 均匀！步长恒为 h = 1/32 = 0.03125

# 目标通道从噪声出发，条件通道钉死在干净值
z_V = where(prompt_V, x0_V, randn()·2.0)
z_T = where(prompt_T, x0_T, randn()·2.0)
x̂_prev = 0                               # 自条件，第一步为零

for i in 0..31:
    t = ts[i];   h = ts[i+1] − t
    x̂_T, x̂_V = model(z_T, z_V, sc=x̂_prev, t, task, whisper_feat)

    # 显式 Euler：dz/dt = (x̂0 − z)/(1−t)
    z_V += h · (x̂_V − z_V)/clamp(1−t, 0.05)
    z_T += h · (x̂_T − z_T)/clamp(1−t, 0.05)

    z_V = where(prompt_V, x0_V, z_V)      # 条件通道每步重新钉回
    z_T = where(prompt_T, x0_T, z_T)
    x̂_prev = x̂

# ---- 出口，按任务分
if task == TTS:
    mel = z_V · latent_std + latent_mean        # (512, 100)
    波形 = VocosVocoder(mel)                     # 冻结。(1, 131072)
else:  # S2T，多一次 forward
    _, _, logits = model(z_T, z_V, sc=x̂_prev, t=1.0, task,
                         whisper_feat, decode_head_active=True)
    token_ids = argmax(logits[tok0 : tok0+48])   # (48,) → 截到第一个 EOS
    转录 = T5Tokenizer.decode(token_ids)
推理的 forward 次数：TTS 是 32 次，S2T 是 33 次（多最后那一次 t=1 的 decode head）。训练每步 3 次 forward，其中 2 次是 no_grad、只为构造目标。

用来做什么flow matching 的 L2decode head 的交叉熵Euler 积分
推理必须用均匀网格，这一点我试错过。一度把采样网格改成匹配训练 t 密度的 logit-normal —— 更差：sigmoid(𝒩(−1.5,0.8)) 的内部点全在 0.5 以下，32 步只覆盖到 t=0.26，最后一步从那里直接跳到 1.0，是一个巨大的 Euler 步。ODE 积分必须覆盖整个 [0,1]，和训练时 t 的密度无关。唯一一次成功从 ELF 无条件生成出通顺英文，用的就是均匀网格。
audio forcing 改的就是 decoder 分支那一列。ELF 原值 decoder_p_mean = 0.8 给 λ 均值 0.69 —— latent 太干净，decode head 直接从它读答案、用不着看音频。改成 −0.5 后 λ 均值 0.392，实测 ce_acc 从 91.7% 掉到 74%（head 变难了，这正是目的），S2T 的 WER 从 106.66% 降到 50.13%。
Solver显式 Euler（一阶）z += h · (x̂0 − z)/clamp(1−t, t_eps)，无自适应步长、无高阶项
ODEdz/dt = (x̂0 − z)/(1−t)由 z = t·x0 + (1−t)·ε·s 对 t 求导得到
t_eps0.05t > 0.95 后分母被钳住，速度上限 20×。否则 t→1 时分母为零
NFE32（TTS） / 33（S2T）S2T 多一次 t=1 的 decode head forward
自条件每步喂上一步的 x̂₀训练时以 0.5 的概率丢掉，推理时一直开
SDE实现了但没用γ 从 0 扫到 3，最终误差只从 0.8140 动到 0.8185 —— 对我们这个模型无效
