统一 TTS + S2T · LibriSpeech 基准 · 2026-10-14

协议审计与两方向结果

这一轮把评测对齐到了文献协议，过程中发现我自己之前报的三个数字是错的。这页先列出所有发现，再给两个方向在对齐协议下的真实数字，最后是 TTS 为什么失败的实测诊断 —— 结论是流匹配训对了，问题在别处。

发现

七项偏离，按严重度排序

编号就是严重度顺序。前三项各自改变了一个已报出的数字。

  1. 打分的波形里有一半是真音频

    改变数字已修

    unified.restore() 每一步都把 prompt 位置钉死在真实值上，所以 tts_rollout 返回的 mel 在 prompt 区装的是录音本身，不是模型输出。按整句打分就等于在给真音频打分。实测每条平均 281 帧被钉死，占音频 50.7%。

    后果：SIM-o 被抬到 0.9601（Voicebox 报 0.593），因为它主要在拿真 prompt 和真目标比；WER 也被抬高（白送 3 秒完美音频）。改成只给生成区打分后，WER 从 63.77 变成 183.59。

  2. 评测处理了 0 条，却打印出一份完整结果

    改变数字已修

    sample_unified.py 里有两个不同的 split 概念：--split 是 LibriSpeech 目录名（用来定位 flac 算 orig 和 ceiling），--cache_split 是 cache 内部切片。我只传了后者，于是 test-clean 的 flac 路径全不存在，所有 clip 被跳过 —— 作业返回 COMPLETED，表里全是 0.00 和 nan。

    这种静默比崩溃危险得多，所以除了传对参数，还加了一条硬断言：0 条时直接报错退出并说明最可能的原因。

  3. test-clean 少了 197 条，全是最长的句子

    改变数字需重做预处理

    preprocess_libri.py 的 --max_s 默认 16.0 秒，于是官方 2,620 条里丢了 197 条（7.5%），抽查的缺失样本是 16.5–28.4 秒。所以 S2T 的 17.20% 是在去掉了全部最长句子的 92.5% 子集上测的，对文献的 2,620 条偏乐观。

    训练集同样被截断：28,539 → 26,752（丢 6.3%），所以我们训的是 92.5 小时而非完整 100 小时。好消息是 TTS 用的 4–10 秒子集完全不触及这个上限，没被污染。

  4. prompt 是比例，文献用绝对秒数

    已修

    我们用 prompt_frac × T，文献（Voicebox / VALL-E / F5-TTS）用绝对 3 秒。比例会让短 clip 的 prompt 短、长 clip 的长，于是 WER 把模型质量和时长分布混在一起。加了 prompt_sec，实测每条 2.997 秒（±1 帧）。

  5. 训练的 prompt 范围覆盖不到评测协议

    下一跑必改

    训练用 prompt_hi = 0.3，所以在 4 秒的 clip 上模型只见过 0–1.2 秒的 prompt。而文献协议给 3 秒 —— 在 4 秒 clip 上是 75%，完全在训练分布之外。审计实测 prompt 占比跨 30%–75%，上半段模型从未见过。这可能是 TTS 失败的一大部分原因，而不只是模型弱。

  6. 没有时长筛选，子集和文献不一致

    已修

    F5-TTS 专门发布了 4–10 秒子集（1,127 条），原因是此前各家英文模型都用不同的未公开子集、数字根本不可比。我们加了 dur_range，筛出 1,237 条，和他们的 1,127 接近。

  7. 任务变体标错 + 缺 SIM-o + 转录不是 PC 版

    部分已修

    我们做的是 continuation（prompt 取同一句开头），常被引用的是 cross-sentence（prompt 取同说话人的另一句）。Voicebox 两个都报，所以该对的是 continuation 的 2.0 / 0.593，不是 1.9 / 0.662。SIM-o 已补上，但用的是公开的 WavLM-base-plus-sv 而非文献的 WavLM-large 微调版，所以趋势可比、数字不逐位可比。转录是纯 LibriSpeech（无标点大小写）而非 LibriSpeech-PC；WER 归一化会去标点，影响较小。

不变量检查

七项全部通过

写了 audit.py 在真实 batch 上验证头条数字依赖的不变量。每项都打印实测量而不只是 PASS —— 只打印 PASS 会藏住它通过的余量。

PASSTTS 行：所有文本位置都是干净条件（prompt_t == t_act）不等位置 0
PASSS2T 行：文本全部是待生成目标（prompt_t 全 0）非零 0
PASSS2T 行：mel 全部是干净条件（prompt_v == v_act）不等位置 0
PASS文本 latent 与 Whisper 特征永不同时非零重叠 0
PASSS2T 行：cond 被任务门控为 0（泄漏修复仍然生效）非零字符 0
PASSWhisper 只写在 mel 区，不碰 token 区token 区 0
PASStoken 区整块文本活跃（不泄漏答案长度）t_act 1.0000

这些检查是为前面第 1、2 项发现写的。两次静默失败都会被「断言这一批应该装什么」挡住，所以现在就断言了。

TTS 方向在多说话人上确实不工作。183.59% 的 WER 意味着生成的音频转写出来基本是别的内容。SIM-o 0.82 看着不低，但它和 183% 的 WER 放在一起说明的是：音频听起来像那个说话人的音色，但说的内容不成句 —— 正是「预测均值」的表现。

教师强制下误差降到 0.26 —— 流匹配目标优化得很好。训练期的 tts/tr 也一直在 0.10–0.23。但在自己的轨迹上误差是 0.92，几乎就是预测均值。轨迹在积分的前四分之一就离开了训练流形，之后再也回不来。

为什么 TTS 的 gap 是 S2T 的两倍

两条原因，第一条确定，第二条是待检验的假设：

  • S2T 最后有一步离散化。token 上做 argmax 对潦草的 latent 很鲁棒，所以 S2T 带着 1.75 的 gap 仍能到 17% WER。TTS 的 mel 直接进声码器，均值化的 mel 就是含混声 —— 没有任何东西兜底。
  • 条件信号的时间对齐（假设）。S2T 的条件是 Whisper 特征，和音频逐帧正确对齐。TTS 的条件是 t5_idx[j] = ⌊j·N/T⌋，把 token 均匀拉伸到帧上。真实语音里 token 时长极不均匀，所以这个信号在主动提供错误信息。教师强制时模型能靠带噪的真 mel 反推真实对齐；自己走轨迹时没这个拐杖。

第二条本来是假设，所以我实测了它而不是断言 —— 用 Whisper 的词级时间戳在真录音上得到参考对齐，和均匀假设比。结果比预想的更严重：

假设成立，而且是定量成立的。均匀拉伸把每个文本单元平均放到「一整个词以外」的位置 —— 这个条件信号不是不精确，是指向了错误的词。audit.py 里这一项以阈值 0.5 个词判定，实测 1.10，FAIL。

这解释了为什么 TTS 的 exposure gap 是 S2T 的两倍：教师强制时模型能从带噪的真 mel 里反推真实对齐，所以错误的 t5_idx 不致命；一旦自己走轨迹，它只剩一个平均偏一个词的信号可用。所以修对齐不是锦上添花，是 TTS 的主线。

下一步

按成本排序

  1. 两个针对 exposure gap 的旋钮 —— 已实现但从未用过

    零训练成本正在跑

    我们一直用 NFE=32, gamma=0.0，即纯 ODE、完全不重加噪。两个扫描在跑：NFE=128（ELF-S2T 用的步数，步长更细则每步误差更小）、gamma=1.0 的 SDE churn（z ← αz + (1−α)·噪声，重加噪本来就是扩散模型里修 exposure gap 的标准手段，把偏离的状态拉回训练流形）。

  2. 三处训练配置必改

    各一轮训练

    prompt_hi 0.3 → 0.75（让 3 秒协议进入训练分布）；--max_s 16 → 更高（补回 1,787 条训练句和 197 条测试句）；encoder 换 whisper-large-v3（特征已算好，40 GB，和 ELF-S2T 对齐）。

  3. 修对齐 —— 这是 TTS 的根因

    要改架构

    三个选项：用我们自己的 S2T 方向产生对齐（同一个网络里就有能做语音→文本的模型，这是统一模型独有的优势，别人要外挂 forced aligner）；在 112 个 token 位置上加一个时长预测头，用非均匀时长代替均匀拉伸；或者干脆不给帧级对齐、只把文本放在 token 区让模型自己学（E2-TTS 的做法，但他们用 10 万小时 / 335M）。

  4. 960 小时

    数据已下载

    train-clean-360（104,014 条）和 train-other-500（148,688 条）已下载解压完毕。磁盘余量从 148 GB 涨到 1.2 TB，所以存 large-v3 特征（555 GB）也放得下，不必做即时计算。4 卡 DDP 已验证（全局 denom 归约出 8406.0，与单卡的 8406.0 完全相等），加速 4.3 倍。
