00 Glossary — every term used below

Some of these are standard; two are names I coined in this project and are flagged as such, because they will not be found in any paper.

path A / path B — my names, not standard

Two ways to turn one continuous 512-d vector into one discrete code id in [0, 4096). This step is unavoidable: the codec decoder only accepts codes, so something has to pick one at the very end.

path A — nearest codebook. Measure the distance from the vector to all 4096 codebook entries and take the closest: argmin_k ‖z − c_k‖. This is what the codec itself does. No learning, no parameters, deterministic.

path B — ELF's learned CE head. A trained linear layer emits 4096 scores; take the argmax. This is ELF's "late discretization", the mechanism that makes ELF different from an ordinary flow model.

Why compare them. If path B is no better than path A, ELF's learned discretizer contributes nothing on audio and you should just use nearest-neighbour — the whole premise collapses. Measured at the noise level the head is trained for: path B 66.96 % vs path A 3.46 %, so it does contribute. Clearer names would be nn_decode and ce_decode; the current wandb keys keep the old names only so the in-flight runs stay comparable.

survival / σ sweep / λ sweep

Take a real latent whose correct code we know. Add noise of growing magnitude. Ask each path to recover the original code. Survival = the fraction of frames where it still returns the right one. A decoder that survives further out is more robust.

σ measures noise added to a clean latent; λ mixes clean and noise as λ·x₀ + (1−λ)·ε, which is the form the CE head is actually trained on. The λ sweep is the fair yardstick — scoring at σ = 0 asks the head for the one thing it never trains on.

exposure gap — my name; the underlying idea is standard "exposure bias"

There are two ways the model can be handed a state at, say, t = 0.7:

(a) teacher-forced — take the true answer x₀ and mix in noise by the formula, z = 0.7·x₀ + 0.3·ε·2.0. This is exactly what every training step looked like.

(b) rollout — start from pure noise at t = 0, run the sampler's Euler steps, and use whatever state the model has built up by the time it reaches t = 0.7.

Training only ever showed the model (a). Inference only ever gives it (b). exposure gap = error on (b) ÷ error on (a), at the same t. A value of 1 means the rollout stays on the manifold the model was trained on. We measure 11.6× at t = 0.7 — the sampler's own state is so far off-distribution that the prediction is 11.6 times worse than it would be on a proper z.

"Exposure" because the model was never exposed to its own outputs while training. Familiar from autoregressive models (teacher forcing vs free running); in an ODE sampler it arises from compounding integration error.

sharpness = ‖x̂₀‖ / ‖x₀‖

How big the model's prediction is compared with the truth. A model that cannot tell which utterance the text specifies hedges by outputting the average of all plausible answers — and an average of many different vectors is shorter than any one of them. So a ratio well below 1 means "blurred conditional mean". Measured 0.50 → 0.57 between 5 k and 10 k steps; the target is ≈ 1.

x₀ — and a naming trap in ELF

ELF's code calls the clean data x0, but it lives at t = 1, because the interpolation is z = t·x₀ + (1−t)·ε — so t = 1 is clean and t = 0 is pure noise. If you are used to diffusion papers where t = 0 is clean, this is backwards. In this project x₀ always means the clean codec latent, whatever t it sits at.

NFE

Number of Function Evaluations — how many times the network runs to produce one sample. NFE = steps × (2 if CFG ≠ 1 else 1) + 1, the +1 being the final decode. It is the honest cost metric: a quality win bought with 129 NFE against a baseline's 8 is not a win.

CFG / SC-CFG

CFG (classifier-free guidance): run the model twice, once with the text and once with the text zeroed, and extrapolate away from the unconditional answer — v = v_u + w·(v_c − v_u). Sharpens adherence to the text at the cost of a second forward pass. SC-CFG is ELF's variant applied to self-conditioning, and it is free at sampling time because the guidance scale enters as an input token rather than a second pass.

p0 / p30

How much real audio the model is given before it must generate. p0 = none, the audio channel is all noise and text is the only conditioning — this is pure TTS, and it is the LJSpeech standard. p30 = the first 30 % of frames are the true latents, so the task is infilling, which is the setting for zero-shot voice cloning on multi-speaker data. Measured: the two give nearly identical numbers at this stage, so the prompt is barely being used.

What the model actually consumes — not waveforms

The chain is wav → [frozen codec encoder] → latent → our model → codes → [frozen codec decoder] → wav. Only the frozen codec ever touches a waveform. Our model's input is a sequence of 512-d vectors, one per 25 ms frame, and its output is a code id per frame. A 9.7 s clip is 231,720 waveform samples but only 386 vectors, and the model predicts 386 integers.

latent / code / codebook

latent — the continuous 512-d vector the codec encoder emits per frame. The flow lives here. codebook — a fixed table of 4096 such vectors, learned by the codec and frozen for us. code — the index of one table entry, an integer 0–4095. The decoder reconstructs sound from codes, so the code is what ultimately has to be right.

02 Why text joins on the channel axis

Stock ELF conditions by prepending along the sequence axis — the German sentence sits in front of the English one, in the same latent space, with a block attention mask. For TTS that choice breaks on three counts.

The three reasons, in order of weight

  1. It keeps x₀ a single distribution. Flow matching transports noise to a fixed target distribution. If text occupied sequence positions, those positions would either become part of x₀ — making the target a mixture of codec latents and text embeddings, two incompatible spaces — or have to be masked out of the loss, which is the prepend design and brings problem 2.
  2. Alignment stops being a search problem. With upsampling, frame j is handed the character it belongs to. This is the single decision ZipVoice's ablation priced at a 12× WER difference.
  3. Sequence length stays T. At 2.66 frames per character, prepending adds ~38 % more positions, and attention is quadratic in them.
And it is why voice cloning comes free. Because the sequence is audio frames only, cond_seq_mask is available to mark something else — the audio prompt. ELF's add_noise, restore_cond and loss_mask then protect exactly the prompt region with no new code, so the model trains on the same infilling task that in-context cloning uses at inference.

03 Exactly how the concatenation works

Stock ELF already concatenates two blocks on the channel axis — [z, x̂₀] for self-conditioning. ELF-TTS adds a third in the same place. That is the whole edit.

# elf_tts/model.py — stock ELF
self.self_cond_proj = _make_linear(2 * text_encoder_dim, text_encoder_dim, bias=True)
...
if x.shape[-1] == 2 * self.text_encoder_dim:
    x = self.self_cond_proj(x.float())

# ELF-TTS: one parameter, threaded through
self.self_cond_proj = _make_linear(n_input_blocks * text_encoder_dim, text_encoder_dim, bias=True)
...
if x.shape[-1] == self.n_input_blocks * self.text_encoder_dim:
    x = self.self_cond_proj(x.float())
# train.py — ELFTTS.forward, where the three blocks meet
def forward(self, z, sc, text_ids, t, *, text_emb=None, drop_text=None, ...):
    if text_emb is None:
        text_emb = self.char_embed(text_ids)          # (B, T, 512)
    if drop_text is not None:
        text_emb = text_emb * (1.0 - drop_text.view(-1, 1, 1))   # CFG, on the text block
    x = torch.cat([z, sc, text_emb], dim=-1)              # (B, T, 1536)
    return self.elf(x, t, ...)

Everything after the projection is byte-identical to stock ELF. The 512-d result goes through text_proj (512 → 128 → hidden), picks up the 12 prefix tokens carrying t, the SC-CFG scale and the mode flag, and runs the unmodified block stack.

CFG acts by zeroing the text block per example. Stock ELF zeroes condition positions instead; redirecting it to the channel is the one change in train_step, and everything else about the loss, the branch draw and the self-conditioning guidance is untouched.

04 How text is repeated onto frames

One line, parameter-free, pure indexing. N characters are spread uniformly across the clip's own T frames, so each character occupies T/N consecutive frames.

# train.py — make_collate
j = np.arange(T)
text[b, :T] = it["chars"][np.minimum((j * N) // T, N - 1)]

# character index for frame j  =  ⌊ j · N / T ⌋
# measured on LJSpeech: T/N = 2.66 frames per character = 66.5 ms at 40 Hz

Where the prompt's transcript goes

Upsampling runs over the clip's full T, so frames [0,P) automatically carry the prompt's characters and [P,T) the rest. In training the prompt is the first 0–30 % of the same clip, which is exactly the infilling task.

Not yet handled: a prompt from a different clip. Real zero-shot cloning uses a separate reference utterance, so the character sequence must be prompt_chars + target_chars upsampled over P + T_syn. The current collator only does the same-clip split. This is a gap in the code, not in the design.

Why no T5, and no text encoder

  • Stock ELF uses frozen T5 because its generation target is text latents. Here the target is audio, so T5's only remaining job would be text conditioning.
  • ZipVoice uses character tokens on LibriTTS and phonemes only on Emilia — characters match the baseline setting we want to compare against.
  • It keeps the parameter comparison honest. A frozen 35 M pretrained text encoder sitting outside the budget is an advantage Grad-TTS and Matcha-TTS do not get.
  • ZipVoice's own ablation prices a dedicated text encoder at 0.35 WER — small. ELF's bidirectional backbone already plays that role.
Implementation trap worth recording. ELF's encode_text carries @torch.no_grad(). A learned character embedding placed there would silently never receive gradient and stay at its random initialisation. The embedding therefore lives in the ELFTTS wrapper, outside that decorator.

06b The loss, written out

Two objectives share one model and one denominator. Everything below is per batch of B examples × L frames.

Masks — what counts

valid[b,j]  = 1 if j < T_b                 # a real audio frame, not padding
prompt[b,j] = 1 if j < P_b                 # the audio prompt, pure conditioning
m[b,j]      = valid[b,j] · (1 − prompt[b,j])  # the only frames either loss sees

The prompt is excluded from both losses and is never noised. That is what makes it conditioning rather than a target, and it is why in-context cloning needs no extra code.

The branch draw

d_b ~ Bernoulli(p_dec)        # ONE draw per example, not per frame
                              # d_b = 1 → CE row    d_b = 0 → L2 row

Branch A — the denoiser (L2), on rows with d_b = 0

t_b   ~ sigmoid(𝒩(P_mean, P_std))                # P_mean −1.5, P_std 0.8 → mean t 0.21
ε     ~ 𝒩(0, I)
z     = t_b·x₀ + (1 − t_b)·ε·s_noise             # s_noise = 2.0
z     ← prompt·x₀ + (1 − prompt)·z               # prompt restored clean

v*    = (x₀ − z) / max(1 − t_b, t_eps)            # t_eps = 0.05, the target velocity

# SC-CFG: on a random half of rows, the target is sharpened by ELF's own guidance
w_b   ~ logU(0.5, 5)
x̂_u   = f(z, 0,   text, t_b, w_b)                # no_grad
v_c   = f(z, x̂_u, text, t_b, w_b)                # no_grad
v*    ← v* + 1[use_sc]·(1 − 1/w_b)·(v_c − v_u)     # detached

# the model predicts x₀ directly; velocity is derived
x̂₀    = f(z_mix, sc_half, text, t_mix, w_b).flow_head
v̂     = (x̂₀ − z) / max(1 − t_b, t_eps)

ℓ₂[b,j] = (1/D) Σ_c ( v̂[b,j,c] − v*[b,j,c] )²      # mean over the 512 channels

Branch B — the decoder (cross-entropy), on rows with d_b = 1

λ[b,j] ~ sigmoid(𝒩(Q_mean, Q_std))              # Q_mean 0.8, Q_std 0.8 → mean λ 0.69
                                                 # drawn PER TOKEN, not per example
z_dec  = λ·x₀ + (1 − λ)·ε'·s_dec                 # s_dec = 1.0
t      = 1                                       # the decoder branch always sits at t = 1

logits = f(z_mix, sc_half, text, t_mix, w_b).code_head     # (B, L, 4096)
ℓ_ce[b,j] = − log softmax(logits[b,j])[ code[b,j] ]

The combination — and why the denominator matters

L = ( Σ_{b,j} ℓ_ce[b,j]·m[b,j]·d_b  +  Σ_{b,j} ℓ₂[b,j]·m[b,j]·(1 − d_b) ) / Σ_{b,j} m[b,j]

One denominator, Σ m, covering both branches. In expectation over the branch draw that is

𝔼[L] = p_dec · mean(ℓ_ce)  +  (1 − p_dec) · mean(ℓ₂)
So p_dec is the actual loss weight between the two objectives, not merely a sampling knob. Had each branch been normalised by its own row count, the two would be weighted 50/50 regardless of p_dec, and the parameter would only control gradient noise. ELF's single denominator is what makes the ratio meaningful — worth knowing before tuning it.

One forward, both branches

z_mix = d·z_dec + (1 − d)·z
t_mix = d·1     + (1 − d)·t
# a single forward runs BOTH heads on ALL rows; the masks select which loss applies.
# so there is no wasted compute beyond evaluating two cheap output heads.

Three forwards per iteration in total: two under no_grad to build the SC-CFG target, and one with gradient. Budget compute at ~3× a plain flow-matching step.

A correction worth recording. I earlier described 0.5 as "ELF's default" and launched a run at that value. It is only the dataclass default; all five released configs set 0.2, and the README's own example config says decoder_prob: 0.2 # 20% decoding (CE) / 80% denoising (L2). Every trainable tensor receives gradient through the same forward. The EMA shadow copy is a second full set of the same parameters, updated in-place and never differentiated.

The one place this can silently break. char_embed lives in the ELFTTS wrapper, not inside ELF's encode_text — which carries @torch.no_grad(). 07 Sampling

z     = ε·2.0 ;  restore_cond → z[0:P] = clean prompt latents
x̂     = 0 outside the prompt
ts    = get_sampling_steps(n, schedule, p_mean, p_std)

for i in 0 … n−1:
    v_c, x_c = model(cat[z, x̂, text],  t)        # SC-CFG is a prefix token: free
    v_u, _   = model(cat[z, x̂, 0],     t)        # only when CFG ≠ 1
    v   = v_u + w_cfg·(v_c − v_u)
    z   = z + (t[i+1] − t[i])·v
    z   = restore_cond(z, prompt)                 # the prompt never drifts

wav   = WavTokenizerDecoder(codes)

NFE = n × (2 if CFG ≠ 1 else 1) + 1. The +1 is the decode forward.

The schedule matters more than it looks. Training draws t ~ sigmoid(𝒩(−1.5, 0.8)), so a uniform 32-step grid queries t = 0.97, 0.94, 0.91 — values the denoiser essentially never saw. ELF's own logit_normal schedule draws the grid from the training distribution instead, and its largest queried t is 0.675, with a single final jump to 1 handled by the decoder branch, which is trained at t = 1. Measured effect in §08c.

ELF's late discretization earns its place on audio: +63 points over nearest-codebook at its working noise level. An earlier σ-sweep from clean latents said the opposite, and that was my measurement error — σ = 0 is the single point the head is never trained on, because the sampler never delivers a clean latent either. The λ sweep is the right yardstick.

A linear unembedding can reproduce nearest-codebook exactly, since argmin_k‖z−c_k‖² = argmax_k(c_k·z − ‖c_k‖²/2). Verified at 100.000 % agreement on 20,000 real frames. So the head is not architecturally limited in either direction — it has chosen robustness over exactness, which is what it was trained to do.

One detail it exposes: with logit_normal, ‖z−x₀‖ and ‖x̂₀−x₀‖ come out identical, because the final Euler step from t = 0.675 to 1 lands exactly on x̂₀. The terminal error simply is the model's x̂₀ prediction error.

Text changes x̂₀ by 35 % at t = 0.05 and by 0.4 % at t = 0.7, and shuffling the characters hurts slightly more than removing them — so content matters, not merely presence. This is the correct shape: at high t the noised latent already carries the answer, at low t text is the only information there is. The text channel is wired correctly and is being used. It also explains why CFG barely moved the rollout — the schedule only queries t ≥ 0.675, where text legitimately does not matter.

08e — what the chain adds up to

Note ‖x̂₀‖ = 11.76 at t = 0.05 against ‖x₀‖ = 21.38. At low t the model emits a shrunken, blurred prediction — the conditional mean — because it cannot yet resolve which utterance those characters specify. That is the signature of an under-resolved conditional model, not a wiring bug. And low t is exactly where the rollout must do its work.
