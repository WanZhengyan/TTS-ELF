机制

同一行里放 mel 帧和 text token，谁加噪就谁是目标

一行序列把语音和文本并排放着，两者都不被重采样到对方的帧率， 所以不需要任何对齐假设。两个任务是同一套计算， 只把「干净」和「加噪」的角色对调 —— 这就是单一目标函数能成立的原因。

对 ELF 的改动

输入从 1024 列加宽到 1736 列

ELF 原本把若干个整块的 text_encoder_dim 拼起来，所以输入宽度总是它的整数倍。 语音通道是 100 维的原始 mel（没有 encoder），宽度不再是整数倍，因此改成显式给定。 通道顺序刻意把 ELF 的两块放在最前面，于是预训练权重原样落进前 1024 列。

一张账本

哪些是 ELF 的，哪些是我加的

原样沿用 ELF

  • flow matching 的公式 z = t·x₀ + (1−t)·ε·noise_scale，v = (x̂₀−z)/clamp(1−t, t_eps)
  • logit-normal 时间分布 t ~ sigmoid(𝒩(p_mean, p_std))，p_mean −1.5、p_std 0.8
  • 两分支 loss 逐行 Bernoulli(decoder_prob=0.2) 把该行路由到 decode head 的 CE 或 denoiser 的 L2，两者共用同一个分母，所以 0.2 就是 CE 的实际权重
  • late discretization 的 decode head gelu(x·proj_kernel + b)·unembed_kernel + b，词表 32100。与 denoiser 读同一份 x
  • 自条件 CFG 两次 no_grad forward 构造锐化后的速度目标：guidance = (1 − 1/sc_cfg)(v_c − v_u)，并以 0.5 的概率丢掉自条件
  • 三组 prefix token 4 个 time、4 个 self-cond-cfg、4 个 model-mode（后者已被 decoder/denoiser 分支占用）
  • 带 num_empty_token 的 RoPE prefix 位置的旋转是恒等，真实位置恒为 0…L−1，与 prefix 数量无关
  • ELF-B 主干与权重 12 层 / 768 宽 / 12 头；ELF-B-owt checkpoint_95085 的 ema_params1
  • 文本 latent 空间 t5-small encoder 输出 ÷ latent_std 0.2

我加的 新

  • input_width 1024 → 1736。放开「必须是 text_encoder_dim 整数倍」的硬编码
  • task_tokens + task_id 2 任务 × 4 token × 768 = 6,144 参数，逐行按任务选取。写法照抄 mode_tokens，因为那组已经被 decoder/denoiser 占用、不能兼做任务标记
  • voice_out Linear(512 → 100)，51,300 参数。接在 ELF 预训练的 final_layer(768→512) 之后，是 denoiser 对语音通道的输出层
  • char_embed + RMSNorm 40 × 512 = 20,480。升采样后的字符，给 TTS 提供逐帧对齐信号；RMSNorm 把它和 z_T 放到同一量级
  • 序列布局 mel 帧与 text token 并排放在一行，不互相重采样
  • 角色对调 用已有的 prompt mask 表达，没有新机制
  • decode head 只在 S2T 行开 d = Bernoulli(0.2) × is_s2t。TTS 是连续目标，没有 token 可预测
语音侧既没有 encoder 也没有 decoder。 语音以原始 log-mel 进入它自己的 100 维通道：没有任何学出来的东西负责产生它， 也没有任何东西把它映射到 token —— 连续目标本来就没有 token 可预测。 文本两者都有，而且两者都是 ELF 自己的：进来时是冻结的 t5-small encoder 查表， 出去时是 ELF 预训练的 decode head。这个不对称是设计，不是遗漏 —— 它也正是 ELF 的 late discretization 真正用上的地方，因为 S2T 的目标确实是离散的。

一步训练

三次 forward，两个分支，一个分母

这一步完全是 ELF 的，只是在它的基础上多了按任务路由。 任务用逐样本 Bernoulli 混合，而不是交替步数： 交替会让任何一步的梯度只来自一个任务，在动量下两个任务部分互相抵消； batch 内混合让每一步的梯度本身就是两者的平均。

验证过的事实

装得进去、路由是活的、decode head 开箱可用

下面每一行都是跑出来的，不是推断。最后一行是最关键的一条： ELF 的 latent 到底是 embedding 查表还是 encoder 输出，config.yml 没有说，而猜错会让 99.58% 的预训练权重变成废的。

检验结果怎么判定的
ELF 权重装载 166 张量 / 99.1% 逐张量按形状匹配；self_cond_proj 部分拷入，712 新列置零
task token 是否生效 输出变化 4.00% 同一输入只换 task_id，相对 L2 差异。为 0 则说明它没到主干
decode head 读 T5 latent 93.1% 干净 latent 送进预训练 head，argmax 还原 token。随机是 0.0031%
条件通路是否打开（S2T） 抹掉音频移动 131% t=0.1 时把 z_V 置零，x̂₀ 的相对移动量
latent 是 encoder 输出还是查表 encoder 输出 ÷ 0.2 让 ELF 无条件采样，它生成通顺英文、x₀ 的 std 稳定在 0.81–0.88； t5 encoder 输出 std 0.1585 ÷ 0.2 = 0.79 吻合， 而 embedding 查表的 std 是 17.26，差 100 倍

现状

架构是通的，生成还不通

必须分开说，因为训练日志看起来是正常的 —— teacher-forced 一直在变好。 而 rollout（真正要的那个）在变差。

rollout 一列是 ‖ẑ−x₀‖ / ‖x₀‖，1.000 就是「什么都不生成」。 TTS 从 0.855 涨到 2.028，三个点单调上升。这不是训得不够，是方向错了。

诊断：exposure gap，根因是高 t 欠训

     t   x̂₀ rollout   x̂₀ teacher-forced   gap
  0.00        0.777               0.765    1.02
  0.25        0.890               0.650    1.37
  0.50        0.924               0.483    1.91
  0.75        0.927               0.402    2.31
  0.88        0.931               0.410    2.27
  （误差全部 / ‖x₀‖，1.00 = 预测均值）

teacher-forced 随 t 单调变好（0.765 → 0.402），健康； rollout 一路平在 0.78–0.93，从不改善，所以 z 永远被拉不到数据流形上。 最说明问题的是 t = 0.88 那行：teacher-forced 时输入 z 本身距 x₀ 只有 (1−t)×noise_scale = 0.24，而模型输出距 x₀ 有 0.41 —— 比直接抄它自己的输入还差，连「高 t 时输出 ≈ z」都没学会。

原因在训练的 t 分布里：t ~ sigmoid(𝒩(−1.5, 0.8)) 只有 3.0% 的样本在 t > 0.5、0.06% 在 t > 0.75 —— 而 rollout 最需要模型的恰恰是高 t 区。ELF 自己能用这个分布， 是因为它在 openwebtext 上跑了 95k 步、早已把高 t 的「抄输入」学会。

还有一个结构性问题没解决：S2T 喂的是原始 mel。 ELF-S2T 那 10.50% 的 WER 建立在冻结的 Whisper encoder 之上， 音频先被编码成音素内容线性可读的表示再作为条件。喂原始 mel， 等于要求 flow transformer 从零学会声学模型。 「语音是连续的所以不需要 encoder」对 TTS 成立 —— 语音作为目标确实不需要，这一点在单独的 mel TTS 上已经验证过； 但对 S2T 不成立，因为那里语音是识别的条件。 补上冻结 Whisper 反而让设计更对称：文本侧冻结 T5、语音侧冻结 Whisper， 两边都是 0 可训练参数。
